# 상장 이력과 상장폐지 권리 처리

2026-09-10 기준으로 다운로드·검토 자료 반영·과거 종목군·백테스트 권리 계산을 연결했다. **전체 시장의 생존편향 제거가 완료된 상태는 아니다.** 현재 DB에는 개별 원문을 검토한 미국 상장 이력 4건·기업행위 5건, 한국 상장 이력 12건·기업행위 12건이 들어 있다. 나머지 수집 자료는 확인된 사건으로 자동 승격하지 않는다.

최근 진행 상태: 1996~2026년 원본 전체를 대조해 정규 주식수 입력에 8,282,325행을 추가했다. 기존 7,102,067행은 값 변경·삭제 없이 유지했으며, 입력은 총 15,384,392행이다. 13,426개의 부적합 원문 관측은 출처를 보존해 격리했다. 새 변경 기록의 5,281개 증권은 후속 팩터·스냅샷 재계산 대상으로 남아 있다. [최신 주식수 입력 상태](../data-lake/gold/survivorship/kr/share_inputs/1996_2026/summary.json)는 입력 반영과 DB 반영을 구분한다.

이미 완료한 2013~2015년·2024년을 제외한 27개 연도 321개월도 원본·현재 가격·native 팩터까지 대조했다. 유효 원본 가격 13,223,749행은 현재 가격과 일치하며, native 누락 18,889,967개를 추가하고 기존 값 38,952개를 정정했다. 기존 값 차이는 2026년 5~7월의 2,558개 증권에 있으며 현재 공개 계산 경로의 가격·주식수·날짜별 원본과 일치한다. 가격 입력 밖의 13,424행은 격리 원문의 가격과 일치하며, native 준비 밖의 29,892개도 원문 주식수 또는 시총과 모두 일치해 보존한다. 운영 DB에서 검증한 최신 값은 79,372,386개이며, 그중 60,443,467개는 기존 값·메타데이터·시각을 유지했다. Gold의 321개 native 월별 파일과 전체 거래일의 FactorLab native 조회 검증도 끝났다.

이후 해당 원천 범위의 이월 값을 포함한 369개월 스냅샷 144,252,414개를 게시·대조했다. 실제 FactorLab의 과거 시점 조회에서 6,717거래일의 연간 시총과 상위 70% 구성, 추가 15개 기준·팩터 사례가 통과했다. 이전에 실패한 2026-07-01 검사도 동일한 코드로 다시 실행해 6개 사례 모두 기대·실제 1,932행이 일치했다. 369개 Gold 월별 파일도 최종 대조를 마쳤다. [나머지 연도 검증 상태](../data-lake/gold/survivorship/kr/capitalization_coverage/20260911/remaining_sources.json)에 완료된 범위별 출력과 31년 통합 검증 결과를 구분한다. 이전 2013~2015년·2024년 범위도 최신 DB에서 native·스냅샷 각각 78개 사례를 다시 실행해 모두 통과했다. [이전 범위 재검증](../data-lake/gold/survivorship/pipeline_verification/20260911_capitalization_prior_scope_recheck/summary.json)을 포함하면 전체 31년의 연간 시총 검증은 7,701거래일이다. 시총·주식수의 Gold 통합은 완료했으며, 다른 주식수 의존 팩터 재계산과 전체 상장 이력 검토는 남아 있다.

같은 차이 키의 실제 FactorLab 조회는 정정 전 38,883개가 모두 이전 값이었고, 게시 후 동일 검증에서는 38,883개 전부 원본과 일치했다. 5개 증권의 69개 값은 종목 마스터·상장 이력·식별자 부재로 여전히 조회되지 않는다. 해당 증권은 140910, 204210, 230980, 464440, 464680이다. 추가 DART 원문으로 상장일·정리매매·상장폐지·잔존 권리를 검토하고 있으며, 가격 수치 검증만으로 상장 이력을 승인하지 않는다. 특히 SPAC의 잔여재산 분배 예정일과 확정 지급을 구분하고, 장기 거래정지와 합병 전 발행사 이력도 별도로 확인한다.

실제 FactorLab의 전체 native 검증은 321개월·6,717거래일 모두 통과했다. 원본으로 계산한 시총 9,318,391행과 상위 70% 결과 6,525,772행을 대조했다. 과거 시점 스냅샷에서 재현한 2026-07-01의 연간·분기·TTM 주식수·시총 6개 누락·오래된 값도 갱신 후 같은 검사로 통과했다. 이후 전체 31년의 369개월을 통합해 최신 native 92,336,244개와 스냅샷 160,728,960개의 값·원천 날짜·회계 메타데이터를 검증했다. Gold의 native·스냅샷 월별 파일 각각 369개도 검증된 DB 출력과 일치하며, [현재 통합 결과](../data-lake/gold/survivorship/kr/capitalization_factors/current.json)에 연결했다. 다른 주식수 의존 팩터와 전체 상장 이력 검토는 계속 필요하다.

추가 상장 후보 204210·464440·464680은 기존 12건을 보존한 별도 검토 목록에 연결했다. 상장일부터 폐지 직전까지 각각 2,383·630·629개 가격·주식수·시총 관측이 Marcap 원문과 일치하며, [가격 미리보기](../data-lake/gold/survivorship/kr/listing_price_preview/20260911/summary.json)에 출처와 보류 조건을 남겼다. 별도 DB의 공개 갱신 명령과 FactorLab에서는 118개월·2,390거래일 전체의 독립 종목군 대조가 통과했고 결과 3,323행이 일치했다. 운영 상장 목록에는 아직 반영하지 않았고, 전체 분할 공시 범위·재무 이력·최종 대가의 확인을 남겨 두었다. 거래정지 시세도 원문 관측으로 보존하며 주문 실행 가능 가격으로 해석하지 않는다.

정규 DART 수집기는 `청산`·`해산`이 포함된 공시도 검토 후보로 보존한다. 공개 갱신 명령에서 두 제목이 누락되는 실패를 재현한 뒤 수정했으며 관련 테스트 19개가 통과했다. 실제 DART 재수집에서도 확인 대상 공시 4건을 모두 받았다. 공시 수집은 청산대금 지급이나 상장 이력 확정으로 자동 승격되지 않는다. [검증 기록](../data-lake/silver/survivorship/financial_research/kr_liquidation_collection_20260911/actual_collection.json)에 원문·해시와 수집 범위를 남긴다.

추가 복구 과정에서 010620의 2015년 마지막 주식수·시총이 2024년까지 이어 쓰이는 문제를 재현했다. 복구 후 실제 공개 계산 함수의 연간·분기·TTM 결과는 2024-01-02 원본의 39,942,149주와 시총 3,411,059.5246백만원에 모두 일치한다. 이는 해당 입력·계산 경로의 검증이며, 새 전체 범위의 native·과거 시점 스냅샷 반영 완료를 뜻하지 않는다.

이후 2024년 `mcap_mil`·`csho`의 연간·분기·TTM native 누락 561,669개를 추가하고, 기존 3,564,579개를 보존한 전체 4,126,248개를 DB에서 검증했다. 이 원천 값이 영향을 주는 2024-01~2026-09 스냅샷 5,509,782개도 반영·대조했다. 스냅샷 키 1,123,512개를 추가하고, 오래된 원천 값·날짜를 사용하던 820,700개를 정정했다. 이후 native 사건이 등장하는 날짜부터는 2024년 값의 적용을 끝내며, 해당 경계와 가격 달력을 반영 전후에 다시 확인했다.

실제 FactorLab의 native·스냅샷 조회 모두에서 2024년 244거래일의 시총 상위 70% 구성이 원본과 일치했다. 스냅샷은 추가 15개 기준·팩터 조합도 확인했다. [2024년 공개 결과](../data-lake/gold/survivorship/kr/capitalization_factors/2024/summary.json)에 범위와 근거를 제공한다. 이는 두 시장 팩터의 2024년 원천 범위 완료이며, 전체 주식수 변경에 따른 나머지 연도·재무 팩터 재계산은 진행 중이다.

앞서 완료한 2013~2015년 범위에서는 시총·주식수 입력의 누락 1,455,590행을 정규 파이프라인으로 복구하고, `mcap_mil`·`csho`의 연간·분기·TTM native 값 8,726,945개를 추가했다. 기존 110,665개는 값·회계 메타데이터·버전 시각을 유지했으며, 전체 8,837,610개를 DB에서 다시 읽어 대조했다. 이 관측값이 영향을 주는 과거 시점 스냅샷 19,374,780개도 반영·검증했다. 새로 복구한 값뿐 아니라 기존 native 값에 스냅샷이 없던 110,665개도 별도로 보완했다.

실제 FactorLab에서 2013~2015년 740거래일의 native 시총 순위·종목 수·상위 70% 구성을 확인했다. 과거 시점 스냅샷을 사용하는 최종 조회의 상태와 근거는 [스냅샷 조회 검증](../data-lake/gold/survivorship/kr/capitalization_factors/2013_2015/snapshot_consumer_verification.json)에 기록한다. 기존 자본·운전자본 팩터의 결측·가용성 조회 10개도 확대된 모집단으로 재검증했다. 미검토 상장 이력에는 현재 마스터를 사용하는 경로가 남아 있어 전체 생존편향 보정이나 전략 성과 검증 완료를 뜻하지 않는다. [최신 범위 요약](../data-lake/gold/survivorship/kr/financial_factors/20260910/full_scope_audit.json)에서 입력·native·스냅샷 상태를 구분한다.

2026-09-10 기준 미국 `LISTING_STATUS` 원본도 갱신했다. Active 14,413행(Stock 8,608·ETF 5,805), Delisted 9,461행(Stock 7,477·ETF 1,984)을 보존했다. 여기서 공급자의 `Stock` 분류를 곧바로 검증된 보통주 상장 이력으로 취급하지 않는다. 9월 9일·10일 Delisted 원문을 동일 심볼·거래소·자산 유형·IPO 일자로 대조하면 595개 항목의 상장폐지일이 하루 뒤로 이동하고, 같은 기준일의 Active·Delisted 양쪽에 동일 식별 조합 10개가 나타난다. 원문 값을 고치거나 자동 확정하는 대신 [날짜·이름 변동 검토](../data-lake/silver/survivorship/financial_research/us_listing_status_20260910/date_stability.json)에 보존하고 SEC 등의 실제 사건 근거와 대조한다.

RTN은 SEC의 2020-04-03 합병 완료 공시에서 개장 전 거래 중단과 1주당 UTC 주식 2.3348주의 교환 권리를 확인했다. Alpha 원문에는 같은 날 종가 116.96·거래량 2,307이 남아 있으므로 이를 거래 가능한 소멸 전 주식으로 사용하지 않는다. 단주는 교환대리인의 합산 매각 후 비용을 뺀 대금의 배분 대상이며, 임의의 당일 종가나 확정 현금 0으로 처리하지 않는다. 구 주식 종류·발행사 이력, 실제 교부·단주대금 지급은 추가 확인 대상으로 남겼다. [RTN 근거와 보류 범위](../data-lake/silver/survivorship/financial_research/us_rtn_source_review_20260911/review.json)에 SEC 원문과 Alpha 가격 해시를 연결했다.

정규 미국 생존편향 갱신에도 이 비교를 연결했다. 원본 SHA-256을 검증한 뒤 각 목록의 가장 최근 과거 스냅샷과 비교하고, 날짜 변경·과거 명칭 변경·양쪽 상태의 식별 조합 중복·동일 행 반복·서로 충돌하는 원문 행을 구분한다. 공개 파이프라인 테스트 21개가 통과했고, 실제 원본 재실행에서 날짜 변경 595건·명칭 변경 1건·양쪽 상태 중복 10건이 독립 감사 결과와 정확히 일치했다. 이전 Active는 6월 30일, Delisted는 9월 9일로 서로 다른 비교 기준일도 기록한다. [실제 파이프라인 대조 결과](../data-lake/gold/survivorship/us/source_coverage/20260910/regular_pipeline_audit/verification.json)는 수집 관측의 검증이며 새 상장 이력이나 현금 대가를 승인하지 않는다.

## 실행

```powershell
& .\.venv-llama\Scripts\python.exe -X utf8 -m engine.workflows.refresh --market us --targets survivorship
& .\.venv-llama\Scripts\python.exe -X utf8 -m engine.workflows.refresh --market kr --targets survivorship
```

`python -m engine.workflows.refresh`의 `all`, `market-data` 실행도 시장자료 갱신 직후 이 단계를 실행한다. `all`에서는 팩터·스냅샷 계산 전에 복원을 마친다. 직접 호출하는 `run_refresh`도 같은 순서를 따른다. `--dry-run`은 계획만 출력한다. `--survivorship-no-download`는 저장된 원문만 사용하며, `--skip-clickhouse`는 silver 가공 자료와 gold 사용자용 파일을 만든다. 기본 비밀키 로더는 환경변수 또는 사용자별 DPAPI 저장소를 사용한다. 키는 원문 출처 URL과 보고서에 넣지 않는다.

### 다시 적재할 때의 적용 범위

검토·등록된 분할·역분할과 상장·권리 이력은 정규 갱신 경로에서 다시 읽는다. 한국 가격과 미국 Alpha Vantage 가격은 원래 거래가격을 보존하고 `adj_close`에 분할·역분할 보정을 적용한다. 기업 합병의 현금·교환주식·조건부 권리는 별도 상장 이력·백테스트 권리 계산에 반영하며 가격에 단순 분할비율로 합치지 않는다. 아직 검토되지 않은 사건까지 확정 처리하거나 전체 시장의 생존편향이 해소됐다고 표시하지 않는다.

| 실행 대상 | 처리 범위 |
| --- | --- |
| `all` | 가격 보정·상장 이력, 재무 등 입력 갱신, 선택한 회계 기준의 팩터·스냅샷 계산 |
| `market-data` | 보정 가격·주식수 적재와 상장 이력 반영. 전체 팩터·스냅샷은 별도 실행 |
| `filings` / `financial-history` | 공시 갱신 / 검토된 과거 공시 등록. 이후 `factors`, `snapshots` 순서로 실행 |
| `stock-splits` | 수정주가 재생성·적재와 과거 팩터 변경 기록. 이후 `factors`, `snapshots` 순서로 실행 |

같은 기준일·옵션으로 다운로드 단계부터 새로 실행하려면 `--no-resume`을 지정한다. 기본 `--resume`은 이전 작업을 이어 실행하므로 완료된 원천 다운로드를 반복하지 않는다. 다음 예시는 연간 기준이며, 분기·TTM까지 갱신하려면 각각의 `--financial-basis quarterly`, `--financial-basis ttm` 계산도 수행해야 한다. `--skip-clickhouse`를 지정하면 DB 재적재는 하지 않는다.

```powershell
& .\.venv-llama\Scripts\python.exe -X utf8 -m engine.workflows.refresh --market kr --targets all --no-resume --financial-basis annual
& .\.venv-llama\Scripts\python.exe -X utf8 -m engine.workflows.refresh --market us --targets all --no-resume --financial-basis annual
```

주식수와 시총 두 팩터를 복구한 것만으로 다른 주식수 의존 팩터의 적재까지 끝나지는 않는다. 예를 들어 005930의 2014-04-01 거래회전율은 현재 공개 계산의 연간·분기·TTM 모두 원본 계산값 0.17410351006353547%와 일치하지만, 팩터랩 native·스냅샷 조회에서는 재계산·적재 전까지 결측이다. [원문·계산 경로 대조](../data-lake/silver/survivorship/financial_research/kr_turnover_public_calculation_20260911/summary.json)는 입력 계산 검증과 DB 조회 복구를 구분한다.

2026-09-11에는 완료된 상위 단계가 새 과거 재무·분할 변경을 가리던 재개 조건을 수정했다. 한국·미국 모두 변경 기록이 남으면 해당 회계 기준의 팩터·스냅샷 단계를 다시 연다. 팩터가 먼저 재계산되지 않은 상태의 스냅샷 실행은 오류를 내며, 변경 없는 재실행은 완료 기록을 재사용한다. 실제 갱신 명령·격리 DB·FactorLab 조회로 신규·정정 공시와 분할·역분할 전파를 검증한다. 이 테스트는 등록된 입력의 전파 검증이며, 공급자 다운로드나 전체 시장의 사건 검토 완료를 뜻하지 않는다. 실행별 근거는 `data-lake/silver/survivorship/financial_research/refresh_historical_resume_20260911`에 저장한다.

OpenDART 문서 요청이 ZIP 대신 오류 본문을 반환하는 경우에도 이제 응답을 해석하기 전에 원본 바이트·출처·해시·수신 시각을 Bronze에 저장한다. 빈 응답은 바이트 수 0과 수신 기록만 남기고 문서 파일을 만들지 않는다. API 키는 출처 URL에 기록하지 않는다. 공개 다운로드 경계의 새 테스트 3개와 관련 테스트를 포함한 88개가 통과했고, 실제 DART의 파일 없음 응답 1건·정상 문서 1건 및 재실행 보존을 대조했다. [수집 검증 결과](../data-lake/gold/survivorship/pipeline_verification/20260911_opendart_response_retention/summary.json)는 이 변경을 기존 원문 부재 캐시의 복구나 별도 웹 뷰어 형식 문제의 해결과 구분한다.

후속 변경으로 API 상태 `014`인 문서를 공개 DART 본문에서 복구하는 경로도 정규 수집기에 연결했다. XML 양식은 실제 DTD와 화면의 전체 문서 검색 요청을 사용하고, 원문 목차의 모든 위치·제목을 검증한다. HTML 양식은 발행사·문서명·날짜를 대조한다. 일부 본문이나 서비스 오류 문구를 완성된 공시로 적재하지 않으며, 거절 응답도 Bronze에 보존한다. API 원문 부재 기록은 복구 후에도 남는다. 실제 공시 3건에서 원본 일치·재실행 보존을 확인했고, XML 목차 81개와 별도 본문 4개도 대조했다. 삼성전자 2018-03-16 분할 정정공시는 CP949 원본과 정정 가족 목록이 유지됐다. 관련 테스트 94개가 통과했다. [최신 DART 수집 검증](../data-lake/gold/survivorship/pipeline_verification/20260911_dart_public_document/summary.json)은 수집 복구와 미완료 재무 항목 검토·전체 사건 반영을 구분한다.

실패한 공개 본문 요청을 다시 시도하려면 개별 분할 파이프라인의 `--force`를 사용한다. 전체 갱신 명령에서는 `--force-full`이 내부 공급자 캐시 재수집에 전달된다. `--no-resume`은 상위 단계의 완료 기록을 재사용하지 않는 옵션이며, 두 옵션의 역할은 다르다. 진행 중인 동일 시장 갱신이 있으면 완료 후 실행한다.

API 원문의 `api:접수번호`와 공개 본문의 정정 가족 ID가 다를 때도, 명시된 접수번호 연결을 같은 증권 안에서 합친 뒤 최신 공시를 선택한다. 철회 본문에 분할 표가 없더라도 이전 계획이 검토 후보에 남지 않는다. 기준일 이후 공시는 연결을 합치기 전에 제외한다. 실제 CLI의 합성 사례 3개로 철회·연결된 정정 이력·기준일·증권 구분을 검증했고 관련 테스트 97개가 통과했다. 실제 2017-05-15 API/XML 원문과 2017-05-18 공개 HTML 정정본을 함께 사용한 실행에서도 날짜별 선택이 일치했다. 이는 두 재무 공시의 버전 선택 확인이며 실제 분할 철회 사건 검증은 아니다. [정정 이력 검증](../data-lake/gold/survivorship/pipeline_verification/20260911_split_correction_family/summary.json)에 범위와 근거를 기록했다. 운영 원장·가격 재생성은 진행 중인 과거 스냅샷 검증 후 수행한다.

직접 공개 DART 검색을 사용하는 수집 경로도 본문 검증 후에만 공시로 등록한다. 읽을 수 없는 최신 정정 본문·HTTP 거절·빈 본문은 Bronze에 보존하고, 해당 정정 이력의 이전 계획이 다시 유효한 후보로 나타나지 않도록 보류 사유를 남긴다. 다른 증권과 과거 기준일의 선택은 유지하며, 원문 재수집에 성공하면 보류를 해제한다. 실제 검색 원문에서 정상적인 빈 결과 표를 오류로 판정하던 경우도 수정했다. 관련 테스트 102개와 실제 삼성전자 공시 2건의 재수집·원본 보존·날짜별 CLI 선택을 확인했다. [직접 수집 검증](../data-lake/gold/survivorship/pipeline_verification/20260911_dart_direct_validation/summary.json)에 근거를 기록했다.

후속 수정으로 본문 요청 이전의 실패, 응답 없이 끊어진 본문 연결, 인증 API 대체 경로의 실패도 같은 보류 정보에 연결했다. 과거의 제공 불가 캐시도 다시 다운로드하거나 기존 바이트를 바꾸지 않고 보류 정보를 보완한다. 응답이 없었던 경우와 빈 HTTP 응답을 구분하며, 확인되지 않은 정정 관계는 만들어 내지 않는다. 공개 수집·실제 갱신 CLI의 새 사례 14개를 포함한 116개 테스트가 통과했고, 실제 삼성전자 공시 2건도 별도 Bronze 경로에 재수집해 원본 보존과 날짜별 선택을 다시 확인했다. [실패·재실행 검증](../data-lake/gold/survivorship/pipeline_verification/20260911_dart_previewer_failures/summary.json)에 근거를 저장했다.

검색 결과에 접수일이 있으면 접수번호 앞자리 대신 해당 날짜를 사용하고, 관련 원공시·정정본은 각각의 정정 이력에 표시된 날짜를 읽는다. OpenDART가 기존 공개 검색 파일을 재사용할 때도 실제 접수일로 조회 범위를 판단한다. 이미 저장된 공시의 잘못된 날짜는 원문을 유지하며 보정하고, 이전 메타데이터 바이트는 Bronze의 별도 버전으로 보존한다. 공개 경계의 날짜 사례 4개와 기존 검증을 합친 120개 테스트가 통과했으며 실제 공시 2건의 날짜 출처·해시·캐시 보존도 확인했다. [접수일 검증](../data-lake/gold/survivorship/pipeline_verification/20260911_dart_publication_dates/summary.json)에 범위를 기록했다.

직접 수집과 API 대체 본문에서 날짜가 없으면 접수번호로 채우지 않는다. 검색 기록과 정정 이력의 날짜가 다르면 두 근거를 보존하고 날짜를 미확정으로 남긴다. 미확정 자료는 갱신 명령의 새 원장 게시를 막으며, ZIP 원문은 정상 수신했더라도 날짜가 확인된 뒤 계산 입력으로 등록한다. 같은 공시의 검증된 자료가 날짜를 확인해 주면 과거 실패 기록을 보존한 채 갱신을 재개한다. 날짜 충돌은 충돌 이후 본문을 다시 검증해야 해제되므로 오래된 승인 사본만으로 해제되지 않는다. 관계없는 미래 공시는 과거 기준일 처리에서 제외한다. 관련 127개 테스트와 최종 코드의 실제 공시 2건·날짜별 CLI 대조가 통과했다. [누락·충돌 검증](../data-lake/gold/survivorship/pipeline_verification/20260911_dart_date_validation/summary.json)에 근거를 기록했다.

후속 수집도 실제 공시일을 사용하도록 보완했다. 날짜 없는 관련 DART 공시는 자신의 안내 페이지에서 날짜를 확인한 뒤 조회 상한을 판단하며, 상한 이후 원문은 보존하되 승인 본문 처리에서 제외한다. KIND 대체 검색은 확인된 DART 공시일을 사용하고, KIND 결과의 날짜는 검색 행에 표시된 날짜를 읽는다. 날짜 미확정 요청은 오류로 남긴다. 공개 경계의 추가 4개 사례와 기존 검증을 합친 131개 테스트가 통과했다. 실제 삼성전자 DART `20180316800856`과 KIND `20180316000856`의 연결을 확인했고, 원본·메타데이터 9개는 재실행 후에도 바이트가 같았다. 표시 시각 `2018-03-16 15:59`는 보존하지만 장중 전략 가용성을 검증한 것으로 해석하지 않는다. [후속 날짜 검증](../data-lake/gold/survivorship/pipeline_verification/20260911_split_followup_dates/summary.json)에 근거와 범위를 기록했다. 캐시된 부모 공시의 정정 이력 재탐색, 과거 캐시 날짜 근거 보완과 운영 자료 전체 재반영은 남아 있다.

| `--survivorship-manifest` | 원문 해시를 고정한 검토 목록. 기본값 `data-lake/meta/survivorship/{market}_reviewed.json` |

미국은 Alpha Vantage `LISTING_STATUS`의 `active`, `delisted`를 함께 받는다. 한국은 OpenDART `list.json`의 I003·I001·B001·E003을 페이지 끝까지 조회하고 관련 공시의 `document.xml` 응답을 보존한다. 문서를 제공하지 않는 `014` 응답도 원문·해시를 저장한다. 실제 접수일 `rcept_dt`와 접수번호를 구분한다. 계획·정정·보류·종료 공시는 검토 대기 후보로 남는다. 공식 규격: [Alpha Vantage 목록 API](https://www.alphavantage.co/documentation/#listing-status), [OpenDART 공시검색](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001).

한국 검토 목록의 주 근거 `source_ids`는 DART만 허용한다. 거래소의 거래정지·상장폐지 확인이 필요한 경우 `kind.krx.co.kr`의 보관 원문을 `supporting_source_ids`로 별도 연결할 수 있다. 출처·해시·발표일을 검증한 보조 근거는 Gold의 `supporting_sources`에 남으며, 해당 행의 정보 가용일은 주 근거와 보조 근거의 발표일보다 빠를 수 없다. 보조 자료가 DART를 대체하지 않으며, 이 지원 추가만으로 000830의 실제 상장·합병 이력을 승인하지 않는다.

검토 파일이 없으면 `summary.json`에 `awaiting_review`를 기록하고 기존 확정 자료를 유지한다. 원문 해시 불일치·중복 사건·유효하지 않은 날짜는 반영을 중단한다. 과거 일괄 다운로드는 이번 실행 이전에 확보된 자료를 재사용한다. 이 단계 자체가 과거 전 종목의 가격·재무자료를 자동 복구했다고 의미하지 않는다.

저장 계층과 파일별 계약은 [데이터 레이크 저장 규칙](data-lake-storage.md)을 따른다.

## 데이터와 계산

- `security_listing_episodes`: 증권 ID·발행사·거래소·상장 구간·근거 공시일. 종료일은 첫 비편입일로 처리한다. 확인된 과거 증권은 현재 `security_master`에서 사라졌어도 종목군에 들어갈 수 있다.
- `security_lifecycle_events`: 현금합병·현금 교환(`cash_exchange`)·주식교환·무대가 소각·상장폐지의 실제 처리일과 권리 완결 여부. 법적 효력일과 일별 가격에 적용할 첫 세션이 다르면 별도로 남긴다. TWTR의 법적 종결일은 2022-10-27, 일별 처리일은 거래중단일인 2022-10-28이다.
- `security_lifecycle_entitlements`: 받을 증권의 ID·단위·수량·인도일·거래 가능일(`tradable_date`). `source_ids`와 원문은 별도 보존된다.
- `security_trading_halts`: 상장 구간과 별도로 보존하는 확정 거래정지 구간. `start_date`는 종가 주문이 실행 불가능한 첫 세션, `end_date`는 다시 가능한 첫 세션으로서 종료일은 제외한다. 종료일이 없으면 공급자의 후속 시세만으로 재개를 추정하지 않는다.

DB는 변경 이력을 추가로 저장하고 시장별 완료 표시를 마지막에 기록한다. 중간 실패는 직전 정상 자료를 계속 노출한다. 같은 자료의 재실행은 중복을 만들지 않으며 다른 시장을 덮어쓰지 않는다. 네 공개 테이블은 확정된 최신 시장별 자료를 읽는 뷰다.

상장·사건 날짜의 DB 투영은 `Date32`를 사용한다. 기존 `Date` 투영에서 1956년 상장일이 1970년으로 바뀌는 문제를 수정했으며, 자료가 동일한 재실행에서도 기존 뷰를 갱신한다. 현재 지원 범위인 1900~2299년 밖의 날짜는 조용히 변경하지 않고 적재를 거부한다. 원본 날짜는 JSON 원장에 그대로 보존한다.

검토한 미국 4종목(ATVI·TWTR·CELG·ALXN)의 Alpha Vantage 가격 18,796행을 수정주가 입력 패널과 `price_daily`에 연결했다. 원문은 보존하고 확인된 거래소 상장 구간 밖의 6행은 계산 패널에서 제외했다. 배당까지 반영한 공급자 수정종가는 별도 보존하며, 수익률 입력은 분할만 조정한다.

같은 발행사의 SEC DEI 발행주식수 공시 180건을 연결했다. 공시 시각을 모르면 접수 다음 날부터 사용하고, 측정일 이후 분할을 주식수에 적용한다. EPS 가중평균 주식수는 시총 분모로 사용하지 않는다. 확인된 공시 이전의 주식수는 결측으로 남는다. 이 방식으로 계산 가능한 시총은 11,059행이며, `market_cap_factors.parquet`와 `fact_daily_factors`의 `mcap_mil`·`annual`·`USD`로 기록된다. 2017년 이후 연구 구간에는 5,043행이 있다.

```powershell
& .\.venv-llama\Scripts\python.exe -X utf8 -m engine.workflows.refresh --market kr --targets financial-history --financial-history-review <검토 JSON>
```

`--financial-history-review`는 여러 번 지정할 수 있고 `--financial-history-output`으로 검증용 목적지를 선택할 수 있다. 기본 목적지는 `data-lake/silver/dart/normalized`이다. `--dry-run`은 파일을 등록하지 않는다. 이 대상은 검토 이력을 등록한다. 후속 팩터 갱신은 정규 이력의 manifest와 재무 계산 코드 버전 변경을 감지해 해당 종목의 과거 구간을 자동 재계산한다. 미검토 수집 자료를 `all` 실행에서 자동 승인하지 않는다. 개별 함수 `publish_reviewed_financial_history`와 모듈 명령도 사용할 수 있다.

가격·시총 적재는 경제적 값의 해시를 기록하고 동일 값은 다시 입력하지 않는다. 검토 메모나 실행 시각만 바뀌어도 중복 적재하지 않는다. 기본 팩터 계산 대상에도 검토된 과거 종목을 포함한다. 이 종목의 재무 결측을 현재 티커 조회로 채우지 않으며, 정규화된 재무자료는 공시 가용일이 있어야 사용한다. 시총 적재만으로 다른 원시 팩터와 스냅샷의 재계산 완료 표시를 바꾸지 않는다. DB 시장별 원장 공개는 완료 표시로 제어하지만 가격·팩터 테이블의 여러 삽입을 하나의 DB 트랜잭션으로 묶는 구조는 아니다.

팩터랩과 백테스트는 매 신호일의 상장 구간에서 확인된 거래정지 종목을 제외하고 같은 날 시총을 적용한다. 그 모집단의 종목 수 기준 `ceil(N × 70%)`를 정한 뒤 팩터 결측·점수 순위를 적용한다. `universe_summary`에는 날짜별 `listing_verified_count`, `listing_unverified_count`, 시총 결측 수와 거래정지 적용 방식이 들어간다. 확인된 이력이 없는 현재 종목은 기존 자료로 계산하는 상태가 명시된다. 업종 분류는 여전히 현재 분류다.

일반 팩터 스크리너도 실제 조회 기준일의 상장·거래정지 이력을 연결한다. 현재 마스터에 없는 과거 증권을 확인된 상장 기간에 포함하고 상장 전·폐지 이후에는 제외하며, 거래정지 종목을 제거한 뒤 시총 모집단과 팩터 순위를 계산한다. 결과 행의 거래소도 해당 날짜의 상장 이력에서 가져온다. 원본 팩터와 스냅샷 조회를 모두 검증하며, 스크리너의 기존 최신 데이터 기준일 선택 정책은 유지한다. 요청일보다 데이터가 오래된 경우 요청일 당시의 실행 가능성까지 검증한 결과로 해석하지 않는다. [일반 스크리너 검증](../data-lake/gold/survivorship/pipeline_verification/20260911_factor_screen_lifecycle/summary.json)에 실제 파이프라인·격리 DB 테스트 근거를 보존한다.

상장 구간은 실제 상장·주식교환·상장폐지의 날짜로 판단한다. 이후 제출된 보고서가 과거의 실제 상장을 확인할 수 있으므로, 보고서 접수일을 상장 시작일로 사용하지 않는다. 근거 접수일은 감사 추적용으로 보존한다. 재무 팩터의 공시 가용일 제한은 별도로 유지한다.

백테스트는 매 리밸런싱을 넘어 보유 주식·현금·현금 미수금·미입고 또는 거래가 제한된 주식 권리를 유지한다. 확인된 현금 지급일 전에는 그 미수금으로 새 종목을 매수하지 않는다. 주식 입고 전 분할도 받을 권리의 가치에 반영한다. 입고했어도 해당 주식의 거래 가능일 전에는 매도·재투자하지 않는다. 날짜 제한이 없는 기존 자료는 이전 인도일 기준을 유지한다. `portfolio_history`에 실제 보유 내역과 권리가 반환된다. 가격 입력은 기존 파이프라인의 **주식분할만 조정한 종가** 기준이다.

확인된 사건 이후의 공급자 잔존 가격을 소멸한 주식의 거래 가격으로 사용하지 않는다. 사건 당시 보유 주식 또는 받을 주식 권리가 남아 있고 대가가 미확정이거나 평가할 수 없으면 검증된 수익률 계산을 중단한다. 사건 전에 실제 매도한 종목은 이후 미확정 대가 때문에 계산을 막지 않는다. 거래정지로 매도할 수 없었던 보유분은 계속 확인 대상으로 남긴다. ALXN의 ADS·CELG의 CVR 및 단주 정산, 035480의 비상장 잔존 지분은 0으로 바꾸지 않는다. 현금 지급일이 확인되지 않은 ATVI·TWTR 대가는 미수금으로 남는다.

기업행위 행 자체가 없는 경우도 검사한다. 확인된 상장 구간이 끝났는데 보유분이나 받을 주식 권리가 남으면, 공급자 시세로 매도·평가하지 않고 미해결 종결 대가 오류를 반환한다. 확정 대가 처리를 먼저 적용하며, 폐지 전 매도와 같은 증권의 연속 상장 구간은 정상 계산한다. 상장 종료일 이후에는 전날 선정된 종목도 신규 매수하지 않는다. 공개 갱신 명령과 실제 격리 DB를 포함한 관련 테스트 202개가 통과했다. [검증 기록](../data-lake/gold/survivorship/pipeline_verification/20260911_closed_listing_outcome/summary.json)에 최초 누락과 조회 조건 수정, 최종 통과를 구분해 보존했다.

거래정지 중에는 거래량이 양수인 공급자 행도 종가 매수·매도에 사용하지 않는다. 보유분은 계속 남으며 마지막 사용 가능한 종가와 `mark_date`, `trading_status`를 반환한다. 그 평가액을 현금으로 바꿔 다음 종목을 매수하지 않는다. 실제 장중 정지 전 매매를 재현하는 모델은 아니며, 종가 주문 기준의 일별 계산이다. 검토 목록의 `trading_halts`는 원문·공시일·상장 이력 연결·겹치는 구간을 검증한 뒤 기존 원장과 같은 시장별 버전으로 게시한다.

## 검증 범위와 남은 작업

공개 실행 경계에서 원문 훼손 거부, 접수일 보존, `014` 응답 보존, 재실행, 시장별 DB 반영, 실패 시 이전 자료 유지, 과거 종목 복원, 시총 상위 70% 적용 순서, 현금/주식 권리와 분할을 검증한다. 테스트 위치는 `tests/test_survivorship_workflow.py`, `tests/test_survivorship_backtest.py`다. 실제 DB 테스트는 세션 임시 테이블 또는 고유 접두어의 테스트 전용 테이블을 사용한다.

받은 주식에 다시 합병이 일어나면 그 후속 사건도 조회하며, 입고 전 권리에도 적용한다. 같은 세션에 여러 사건이 발생해 선후관계를 알 수 없으면 별도 검토를 요구한다.

전체 완료에는 나머지 과거 증권의 식별·상장 구간, 심볼 재사용, 당시 가격·재무·시총 자료와 실제 거래 가능일 연결이 필요하다. 정지 중 분할과 사건의 주당 기준, 단주 정산·조건부 권리의 실제 가치, 업종 분류의 과거 이력도 추가 검증 대상이다. 기존 고정 전략과 2024년 이후 평가 구간은 바꾸지 않았고, 양국 샤프 1 초과를 달성했다고 주장하지 않는다.

## 분기·TTM 반영 및 ROE 정정 — 2026-09-10

## 회계정보와 스냅샷 행 선택 정정 — 2026-09-10 후속

시장 팩터 게시기는 숫자가 같은 경우에도 회계연도·회계기간·통화가 달라졌는지 확인한다. 앞선 숫자 게시에서 누락했던 회계정보 264,296개 행을 추가 버전으로 반영하고, 1,366,272개 최신 행의 값과 회계정보를 모두 다시 대조했다. 숫자 값은 변하지 않았다. 변경 전후 행과 공개 파일은 새 게시 실행 `20260910T130830Z_9c9ae1c4`에 보존했다.

## 자본 계정 추가와 계산 불가 상태 보존

003410과 035480의 공시 103건을 원문 표시 범위·단위·금액까지 대조했다. 003410에서 다른 채권·채무와 합쳐지지 않은 매출채권 12개, 매입채무 61개를 추가로 인정했다. 035480의 합산 계정은 순수 매출채권·매입채무로 바꾸지 않았다. 차입금 구성과 합산 범위는 별도 검토가 필요하며 이번에 부채 총액을 확정하지 않았다.

같은 공시의 계정 추가는 기존 manifest 해시와 검토 이유가 일치해야 한다. 이전 금액·공시일·회계기간·연결 범위·원문 해시는 그대로 유지하고, 이전 manifest는 silver에 보관한다. 실제 반영 후 연간·분기·TTM을 다시 읽어 기존 7개 재무 지표와 가용일이 유지되는지 확인했다.

독립 계산 과정에서 분기 재고·매출채권·매입채무 회전일수가 분기 흐름에 365일을 곱하는 문제를 확인했다. 기존 365일 기준을 유지하면서 단독 분기는 흐름을 연율화한다. 연간·TTM은 365, 단독 분기는 91.25를 곱하며 기존 전년 동기와 현재 잔액의 평균 방식은 유지한다. 12종목·3개 기준을 재계산한 유효 후보는 4,253,233개다. 이전 준비 자료보다 21,987개가 추가됐고, 기존 분기 재고 회전일수 3,556개가 정정됐으며 제거된 키는 없다. 원문 계정으로 별도 계산한 자본 관련 11개 팩터 32,541개가 모두 일치했다. 관련 기간 단위·재무 이력 테스트 94개와 2개 서브테스트가 통과했다.

새 공시에서 계산 근거가 사라져도 스냅샷이 이전 유효 값만 이어 쓰는 문제도 확인했다. 스냅샷의 전체 재생성·증분·단순 복사는 최신 행을 선택하기 전에 결측을 제외하지 않는다. 팩터 갱신 파이프라인은 `include_abstentions=True`로 첫 결측과 유효→결측 전환을 저장한다. 연속 결측 날짜는 같은 상태를 이어 쓰며, 새로운 유효 값이 나오면 그 날짜부터 회복한다. 일반 계산 API의 기본값은 유효 값만 반환하는 기존 계약을 유지한다. 재무 이력 완료 서명에는 적재기와 스냅샷 구현도 포함해 이전 완료 표시가 변경된 로직을 건너뛰지 못하게 한다.

## 시총 입력의 정규 파이프라인 복구 — 2026-09-11

`normalize_shares`는 종목별 KRX CSV와 등록된 과거 원본을 함께 읽는다. 입력 원본은 bronze 안에 있어야 하며, 등록한 바이트의 SHA-256, 관측 연도, 종목코드, 양의 정수 주식수, 가격×주식수와 시총을 검증한다. 같은 종목·거래일의 값이 충돌하면 이전 silver 파일을 보존하고 실패한다. 등록이 없는 경우에는 기존 종목별 입력을 사용한다. `output_path`로 silver 안의 별도 스테이징 파일을 만들 수 있다.

### 2026-09-11 시총·주식수 스냅샷 복구

2013~2015년의 검증된 관측값 8,837,610개를 새로 추가한 native 키와 보존한 기존 키로 나누어 처리했다. 각 값은 다음 native 관측이 나타나기 전까지 적용한다. 다음 관측값이 결측이어도 기존 값의 영향은 그 날짜에 끝난다. 2016년 이후의 첫 후속 관측일을 반영 전후에 다시 읽어 일치함을 확인했고, 165개월의 스냅샷 19,374,780개를 독립 계산·공개 파이프라인 SQL·실제 DB 재조회로 대조했다. 두 범위의 스냅샷 키 교집합은 0개다.

실제 팩터랩의 과거 시점 조회로 기존 native 값의 별도 누락도 발견했다. 2013-03-28의 상위 1,025종목 중 17종목이 스냅샷 없이 빠졌고, 35개 증권의 기존 native 관측 110,665개 전부에 같은 키의 스냅샷이 없었다. 이를 보완한 뒤 같은 조회에서 1,025종목과 원본 기준 시총이 모두 일치했다. 실패·성공 조회와 DB 원인 확인은 silver의 `kr_historical_capitalization_snapshot_first_consumer_20260911`에 보존한다.

이번 복구는 정규 주식수 입력의 보존과 검증된 관측 구간의 native·스냅샷 반영이다. 재무 이력 전체 재계산 완료 표시는 바꾸지 않았다. 미검토 발행사·상장 이력·최종 대가, 나머지 재무 팩터 입력의 검토도 계속 필요하다.

## 한국 과거 주식수 입력 변경의 후속 갱신

`normalize_shares`의 기본 출력은 교체 전에 종목·날짜별 변경을 기록한다. `historical_sources.json`이 바뀌면 `--targets factors`가 가격 달력이 최신이어도 등록 원본을 다시 정규화한다. 완료된 재개 체크포인트가 있어도 변경된 종목의 최초 변경일부터 가용 가격의 마지막 날짜까지 다시 계산한다. 시총·주식수에 한정하지 않고 실제 계산 가능한 의존 팩터를 함께 준비한다. 원문 근거가 없는 팩터를 수치 0으로 승인하지 않는다.

계산 결과는 먼저 silver에 준비하고 기존 값과 비교한다. 달라진 키와 철회된 값만 새로운 버전으로 넣은 뒤 DB에서 다시 읽어 대조한다. 과거 주식수 등록을 철회하면 여러 달 뒤에 남아 있던 거래회전율 등도 결측으로 취소한다. 입력 해시와 변경 기록을 확인하며 정규화 밖에서 CSV를 수정한 경우에는 정상 완료로 건너뛰지 않는다.

`--targets snapshots`는 같은 재무 기준의 팩터 재계산이 끝난 뒤 실행한다. 스냅샷도 완료 체크포인트를 재검사하고, 격리된 테이블에서 실제 as-of SQL로 준비한 뒤 변경분을 반영한다. 연간 완료가 분기나 TTM 완료를 대신하지 않는다. 공개 FactorLab 조회를 사용하는 격리 DB 테스트로 과거 주식수·시총·거래회전율, 등록 철회, 중단된 파일 교체의 정규화 재시도, 기준별 선후 관계, 완료 후 재실행을 검증한다.

원본은 bronze, 변경 기록·계산·DB 전후 자료는 silver, 검증된 사용자용 월별 값은 gold에 저장한다. 세부 경로는 [데이터 저장 규칙](data-lake-storage.md)에 있다. 이 기능 도입 전에 복구한 2013~2015년 주식수 입력이 다시 동일하게 정규화됐다는 사실만으로 모든 의존 팩터의 과거 재계산을 완료 처리하지 않는다. 이미 검증한 시총·주식수 2개 팩터의 공개 범위와 나머지 재무·시장 팩터의 재계산 범위를 구분한다.

단기·장기 부채 중 한쪽이 없으면 0처럼 합산하는 오류는 공개 갱신 명령과 FactorLab에서 재현한 뒤, 두 구성 금액이 모두 확인될 때만 합산하도록 수정했다. 명시된 0원은 유효한 공시 값으로 유지한다. [별도 수정안 검증](../data-lake/gold/survivorship/pipeline_verification/20260911_debt_abstention_candidate/summary.json) 후 한국 31년 통합 출력을 마친 시점에 운영 코드에도 적용했다. 운영 코드의 실제 갱신 명령·격리 DB를 포함한 회귀 테스트 75개와 하위 검사 4개가 통과했다. 누락의 두 방향, 명시된 0원, 완전한 합계와 후속 공시로 기존 팩터·스냅샷을 철회하는 경로를 검증했다.

실제 한국 12종목·미국 4종목의 연간·분기·TTM 판독 결과 939개 관측도 같은 원천 파일 246개로 다시 계산했다. ATVI·CELG의 한쪽 부채만 확인된 79개 관측에서 합계·부채비율이 결측으로 바뀌었고 원천 계정·공시 날짜는 유지됐다. 이는 공시 79건이나 일별 팩터 79개를 뜻하지 않는다. 파생 지표 변화는 별도로 보존했다. [운영 코드와 실제 입력 검증](../data-lake/gold/survivorship/pipeline_verification/20260911_debt_abstention_main/summary.json)은 코드 수정과 운영 DB 재계산을 구분한다. 미국 네 종목의 일반 SEC 정규화 파일은 이후 별도 변경 감지에도 포함했다. 전체 가용 Alpha 가격 기간의 293개 대상 팩터·세 회계 기준 최초 준비본 6,692,912행은 Silver에 보존했으며 native·스냅샷 게시와 완전한 차입금·리스 범위의 검토는 아직 남아 있다.

최초 미국 준비본의 부채비율을 원천 계정 합계·공시 다음 날 가용일과 독립 대조한 결과, 12개 종목·기준 조합 중 10개가 일치했다. ALXN 분기·TTM에서는 2017-01-20~2017-02-16의 20거래일씩 값이 달랐다. 2016년 3분기는 2017-01-04에 알려졌는데, 일별 결합이 2017-01-19에 공시된 2015년 말 자료를 뒤늦게 선택하면서 최신 결산기간을 과거로 되돌렸다. [준비본과 후속 검증 상태](../data-lake/gold/survivorship/us/financial_rebuild_preparation/20260911/summary.json)에 날짜별 비교를 연결했다. 이 부채비율 대조가 전체 293개 팩터의 승인이나 차입금·리스 총액 검토를 대신하지 않으며, 과거 기간 정정이 현재 기간의 성장률·평균잔액에 미치는 영향도 함께 확인한다.

이후 일반 SEC 정규화 입력에도 공시 당시 알려진 기간별 자료만 계산하는 경로를 연결했다. 늦게 공시된 과거 기간이 최신 기간을 덮어쓰지 않으며, 그 과거 잔액은 공개된 뒤부터 최신 기간의 평균잔액에 참여한다. 실제 갱신 CLI·격리 DB·FactorLab native·스냅샷 조회의 새 5개 사례와 기존 회귀 테스트를 포함한 97개가 통과했다. 추가 대조에서 분기 ROE 평균이 연간 요구수익률을 사용하는 RIM의 대체 입력으로 유입되는 문제도 재현해 차단했다. 이 최종 변경은 분기 결측·TTM 유지 사례를 포함한 관련 53개 테스트를 통과했다. 최종 미국 준비본 6,668,961행은 Silver에 보존했고, 부채비율은 4종목·3기준의 전체 보유 주가 기간에서 12개 조합 모두 독립 계산과 일치해 기존 40개 일별 불일치가 해소됐다. [최종 코드와 재계산 검증](../data-lake/gold/survivorship/pipeline_verification/20260911_us_period_vintage/summary.json)에 실패·통과 기록과 원천 해시를 연결했다. 일반 파일에서 사라진 과거 공시 버전 복원, 다른 파생 팩터의 검토와 운영 native·스냅샷 반영은 남아 있다.

검토된 과거 종목의 일반 정규화 파일·해당 발행사의 공시일 메타데이터·계산 버전을 재개 조건에 연결했다. 수치 정정, 공시일 변경, 파일 철회, 빈 검토 이력으로의 전환이 생기면 과거 팩터와 스냅샷을 다시 처리하며, 이전 재계산 시작일도 유지한다. 다른 발행사의 메타데이터만 바뀌거나 입력이 같으면 완료한 단계를 재사용한다. 재무자료 철회로 팩터 열 전체가 없어질 때는 결측 전환 사건을 남겨 더 오래된 값이 스냅샷에 되살아나지 않게 했다. 확장 검사 133개 중 132개가 통과했고, 임시 데이터 경로의 기본값이 고정되는 1개 회귀를 수정한 뒤 해당 ELT 검사와 신규 미국 8개·한국 1개 공개 실행 사례를 포함한 25개가 통과했다. 실제 미국 4종목·3기준·팩터/스냅샷 24개 재계산 대상을 읽고, 3개 기준의 dry-run CLI도 확인했다. ALXN·ATVI·CELG는 1999-11-01, TWTR은 2013-11-07부터 보유 가격 범위를 다시 처리하도록 잡혔다. [입력 변경·철회 검증](../data-lake/gold/survivorship/pipeline_verification/20260911_financial_source_refresh/summary.json)은 일반 정규화 출력부터의 전파와 실제 계획 검증이다. 운영 DB 반영이나 전체 원문 수집·공시 버전 완전성을 뜻하지 않는다. 이전 준비본은 새 결측 사건 처리 전의 기록으로 보존하며, 새 게시에는 최종 코드로 준비·대조한 자료가 필요하다.

SEC 원본에서 10-K·10-Q 및 정정 양식의 보존 관측 67,066개와 값이 다른 항목·단위·기간 조합 2,895개도 정리했다. 이는 같은 기간의 공시별 관측과 반올림·표시 기준 등의 검토 후보이며 정정 사실을 일괄 승인한 수치가 아니다. 원문 파일은 Bronze에서 해시가 유지됐고, [공시별 관측 목록](../data-lake/silver/survivorship/financial_research/us_financial_source_refresh_20260911/sec_retained_versions/summary.json)은 Silver에 보존했다. 공시 묶음이 있는 기간의 우선순위와 회계기간 의미를 확인한 뒤 재무 이력을 복원해야 한다.

RTN의 증권 식별은 SEC 원문으로 별도 검토했다. 1997년 합병에서는 기존 Raytheon 보통주가 HE Holdings에서 이름을 바꾼 발행사(CIK 1047122)의 B종 주식으로 1:1 전환됐다. 2001년에는 A·B종이 단일 보통주로 통합됐다. 같은 날의 역분할·재분할은 계좌별 20주 미만 보유자를 현금 청산하고 20주 이상 보유자의 주식 수는 유지하는 조건이므로, 일률적인 수정주가 계수만으로 권리 처리를 대신할 수 없다. 2001년 Form 15는 A·B종 등록 종료이며, 보통주의 보고 의무는 계속된다고 명시한다. 이를 발행사 전체의 상장폐지로 해석하지 않는다.

새 검토는 Alpha 가격 5,139행 모두를 보존하면서 통합 전 387행, 새 보통주 구간 4,751행, 공식 거래 종료 뒤 잔여 호가 1행으로 구분했다. SEC 연차보고서의 주식 종류별·분기별 고저가 30개 셀을 원문에서 읽고 Alpha의 장중 고저가와 종가 극값을 각각 비교했다. 이 비교는 개별 일별 가격의 증권 식별 승인이 아니다. 2001년 5월 15일 첫 거래는 원문에 예정으로 표현돼 있고, 이전 B종 가격의 공급자 연결과 실제 현금·교환주식 지급도 추가 확인이 필요하다. 원문 20건과 경로 오류 응답 1건은 `bronze/sec/listings/share_identity_20260911/RTN`, 검토·전체 행 구분·재실행 검증은 `silver/survivorship/financial_research/us_rtn_share_identity_review_20260911`, [사용자용 검토 결과](../data-lake/gold/survivorship/us/rtn_share_identity/20260911/summary.json)는 Gold에 저장했다. 원문 수집기를 다시 실행해 20건의 원본·메타데이터가 그대로 유지됨을 확인했으며, 운영 상장 이력·가격·팩터에는 아직 반영하지 않았다.

한국 등록 후보 204210·464440·464680은 상장 연도부터 2026-09-10까지 DART 전체 공시 목록 636건, 사업·분기·반기보고서 21건, 청산·해산 공시 4건을 대조했다. 보고서에서 직접 읽은 발행주식 수가 기존 원본 시세 3,642행과 일치했다. 상장 당시 증권신고서와 2017년 정정 분기보고서를 추가 대조해 204210의 2018년 사업보고서에만 2017년으로 적힌 93만 주 증자가 2014년의 기존 증자임을 확인했다. 원래 날짜·원문은 보존하고, 2017년에 새 증자나 가격 조정을 생성하지 않는다. 464680의 표 단위가 빈 곳은 같은 절의 명시된 주식 수·원화 자본금으로 대조했으며, 자본금 표가 생략된 다른 2건은 변동 없음이나 0원으로 처리하지 않았다.

세 종목의 전체 보존 가격 구간에서는 추가 분할·병합 계수가 필요한 사건을 찾지 못했다. [자본·분할 원문 검토](../data-lake/gold/survivorship/kr/proposed_listing_capital_history/20260911/summary.json)와 [검증 기록](../data-lake/gold/survivorship/kr/proposed_listing_capital_history/20260911/verification.json)에 원문 표 507행, 날짜별 발행주식 수 21건, 과거 증자 표 35행과 판단 근거를 보존했다. 이 결과는 세 가격 구간의 검토이며, 전체 시장이나 미검토 재무 이력의 승인이 아니다. 두 스팩의 청산 안내는 공모 전 주주를 예치금 분배에서 제외하고 최종 금액을 추후 정한다고 명시하므로 실제 지급 금액·지급일은 여전히 미확정이다. 운영 등록과 재무 팩터 적재는 남아 있다.

RTN의 후속 2002년 SEC 위임장에서는 A·B종 모두 1997-12-18에 NYSE 거래를 시작했고 2001-05-14에 마지막으로 거래했다고 명시한다. 새 보통주의 성과 측정과 투자 기준일은 2001-05-15이다. 동시기 재분류 완료 공시와 Alpha 관측을 함께 대조해 새 보통주의 일별 구간 경계를 뒷받침했다. Alpha의 2001-05-15~12-31 공급자 수정종가 변화는 공시의 총수익 지수 112.98과 표시 반올림 범위 안에서 일치한다. 반면 2000년 말~2001-05-14 변화는 A·B종 지수 어느 쪽과도 해당 범위에서 일치하지 않아 이전 387개 가격의 종류는 계속 보류한다. 이는 가격 오류나 수정계수를 확정하는 근거가 아니다. [최신 거래 구간 검토](../data-lake/gold/survivorship/us/rtn_share_identity/20260911/current_review.json)에 SEC 원문·캐시 재실행·비교 수치를 연결했다. 공급자 수정종가는 이 대조에만 사용했으며 전략 가격 입력은 분할만 보정한다. 원문 2건은 Bronze의 별도 실행 범위에 저장해 기존 RTN 근거 30개의 해시를 유지했다. 소액 계좌 현금화, 2020년 단주·교부·지급, 재무 이력과 실제 운영 등록은 여전히 남아 있다.

ALXN의 2015년 말 재무상태표는 원래 10-K, 2016년 1분기 비교 열, 2017년 10-K/A의 세 공시에서 12개 수치를 대조했다. 2016년 비교 수치의 차이는 해당 공시가 명시한 부채 발행비용 8,635,000달러·26,714,000달러 재분류와 일치한다. 2017년 정정본은 내부통제 보고를 변경하면서 원래 재무 수치를 유지한다고 명시하므로, 늦게 제출됐다는 이유만으로 2016년 표시 변경을 되돌리는 근거로 삼지 않는다. 원래 공시일은 SEC 접수 화면에서 2016-02-08로 확인했지만 현재 기간별 메타데이터에는 2017-01-19 정정일만 남아 있다. [공시별 원문 대조](../data-lake/gold/survivorship/us/financial_version_reviews/20260911/ALXN/summary.json)에 본문·접수 정보와 재실행 검증을 연결했다. 이 검토는 전체 SEC 공시 묶음이나 재무 이력의 운영 반영을 대신하지 않는다.

SEC 정규화는 기간별 최종 CSV와 별개로 `silver/sec/normalized/accessions/{symbol}/manifest.json`에 공시번호별 선택 결과를 연결한다. 정규화한 회계연도 범위와 해시로 검증하는 CSV를 보존하며, `--no-debug`에서도 이 자료는 유지된다. 검토된 과거 증권의 엄격한 로컬 일별 계산은 공시별 입력을 사용하고, 아직 이 방식으로 정규화하지 않은 연도는 기존 날짜 근거를 사용한다. 공시번호별 파일 변경도 팩터·스냅샷 재개 조건에 포함된다. 표지 주식수만 있는 관측은 보존하되 새로운 재무제표 기간으로 사용하지 않는다. SEC 공시 묶음의 현재 결산일과 다른 항목은 현재 기간 값으로 선택하지 않으며, 그 공백을 낮은 우선순위의 자료로 채우지도 않는다.

원래 공시의 가용성, 이전 공시만 수정한 재실행, 계정 누락, 원천 추적, 주식수만 있는 공시와 다른 결산일의 항목을 실제 정규화 CLI·갱신 CLI·격리 DB·FactorLab에서 확인했다. 기간 선택 보완 전의 관련 69개 테스트와 하위 검사 7개가 통과했고, 최종 변경 후에는 새 공개 사례 9개를 포함한 관련 48개 테스트·하위 검사 7개가 통과했다. 두 결과는 중복 검사이며 합산한 독립 사례 수가 아니다. 실제 네 종목의 최종 공시별 준비본은 8,462행이다. CELG의 다른 기준일 항목 4개를 제외한 기간별 8,365행은 기존 값과 일치했다. ALXN의 2015년 부채비율은 공시일인 2016-02-08까지 사용되지 않고 다음 날부터 0.4185023253290866으로 계산됐다. 원본·운영 입력 106개는 해시가 유지됐다. [공시별 정규화·재적재 검증](../data-lake/gold/survivorship/pipeline_verification/20260911_sec_accessions/summary.json)에 실패·통과와 실제 계산 근거를 연결했다.

이 변경은 정규화기가 현재 기간으로 선택한 공시 버전을 보존하는 경로다. 모든 비교기간·과거 XBRL 문맥을 복원한 것은 아니며, 비재무 정정의 범위, 회계 표시 변경, 분기 누적값과 가중평균 주식수·EPS의 계산 의미는 추가 검토가 필요하다. 실제 네 종목의 운영 정규화·native·스냅샷은 이번 검증에서 게시하지 않았다. 이전 준비본으로 새 게시를 승인하지 않으며, 최종 코드와 새 입력으로 다시 준비·대조해야 한다.

SEC 공시번호별 입력의 EPS와 가중평균 주식수에는 같은 공시·태그·단위의 기간별 관측을 함께 보존하도록 추가했다. XBRL에서는 문맥의 차원도 일치해야 한다. 분기값은 실제 분기 관측을 사용하고, 연간 누적 EPS나 평균 주식수를 차감하지 않는다. 연말 TTM은 공시된 연간값을 유지한다. 연말 이외 TTM의 EPS·평균 주식수는 독립된 기간 근거가 없으면 결측으로 남기며, 이 공백을 기말 주식수로 채우지 않는다. 현금흐름처럼 합산 가능한 항목의 TTM 계산은 유지한다. 원본 공시에 해당 분기값이 없거나 단위가 다르면 CompanyFacts의 값으로 우선순위 경계를 넘어서 채우지 않는다.

같은 연간·누적 CSV가 유지되고 분기 관측만 바뀌어도 공시별 파일 해시가 달라지므로 완료된 팩터·스냅샷을 다시 처리한다. 실제 정규화·갱신 명령, 격리 DB와 FactorLab 조회로 이 경로를 확인했다. [분기·주당 지표 검증](../data-lake/gold/survivorship/pipeline_verification/20260911_us_per_share_periods/summary.json)에 공개 실행 9개 사례와 회귀 검사를 연결한다. 실제 ATVI의 2010년 2분기는 SEC 원문과 기본 EPS 0.18, 희석 EPS 0.17, 기본 평균 주식수 1,232,000,000주, 희석 평균 주식수 1,248,000,000주가 일치했다. 별도 준비 영역의 공개 일별 계산 66행에서 공시일인 8월 6일까지 이전 분기를 유지하고 다음 거래일인 8월 9일부터 새 값을 사용했다.

이 처리는 기간 관측을 포함해 다시 정규화한 SEC 공시별 입력과 엄격한 로컬 일별 계산에 적용된다. 현재 분기 기간 후보는 60~120일, 연간 후보는 330~400일로 제한하고 동일 기간의 값이 충돌하면 사용하지 않는다. 결산기 변경·모든 비교기간의 분할 전후 주식 단위·온라인 및 기존 기간 전용 판독 경로까지 검증한 것은 아니다. 운영 native·스냅샷 재적재와 전체 시장 생존편향 해소도 별도 미완료 상태로 유지한다.

같은 기간 정보는 합산 가능한 손익·현금흐름 계정에도 적용한다. 원본 XBRL의 10-K라는 양식만으로 짧은 분기 구간을 연간값으로 분류하지 않는다. 같은 공시의 분기값이 있으면 이전 공시의 누적값을 빼서 대체하지 않고 해당 분기값을 사용한다. 앞선 관측이 독립 분기값이면 누적 기준선을 복원해 다음 누적값에서 차감하며, 중간 기간이 없으면 차감 결과를 만들지 않는다. 새 누적 공시 자체가 알려지면 이후 분기의 기준선으로는 사용할 수 있다.

연간 구간이 직접 공시됐으면 그 금액을 TTM에도 사용할 수 있다. 연간값이 없고 동일 공시·태그·단위·문맥에 네 개의 연속된 분기가 모두 있으면 연간 합계를 복원한다. 기간 누락·겹침·값 충돌이 있으면 합산하지 않으며, EPS와 가중평균 주식수에는 이 합산 규칙을 적용하지 않는다. 기존 비교기간의 가용일을 앞당기거나 모든 과거 비교기간을 복원하는 기능은 아니다.

실제 ATVI 2010년 10-K의 분기 매출원가는 533·367·349·878백만 달러이며 합계 2,127백만 달러다. 기존에는 마지막 분기 878백만 달러를 연간값으로 사용했다. ALXN 2019년 매출총이익도 네 분기 합계 4,596.6백만 달러로 복구했다. 이 변경 후 네 미국 종목·세 기준·293개 팩터의 준비본은 6,704,660행이며, 9개 기준 지표의 507,492개 값은 공시별 기간 계산과 일치했다. [기간 처리와 실제 원문 검증](../data-lake/gold/survivorship/pipeline_verification/20260911_us_disclosed_flow_periods/summary.json)에 근거를 연결한다.

동시에 CELG의 2010년 2분기 R&D에 전체 비용 대신 Agios 협업 계약금 121.2백만 달러가 선택된 문제를 확인했다. 원문의 분기 총액은 342.761백만 달러, 누적 총액은 547.418백만 달러이며, 동일 공시의 대체 태그에도 이 금액이 존재한다. 선택된 canonical 입력과 산술이 일치한다는 사실이 원천 계정 범위의 적정성을 증명하지 않는다. 이 계정 선택과 의존 팩터를 보완하기 전에는 새 준비본으로 운영 native·스냅샷 게시를 완료 처리하지 않는다.

후속 검증에서는 정규 SEC 수집기로 CELG의 `0000950123-10-072016` 공시 묶음을 복구했다. 공시별 XBRL을 사용하자 기존 기간 선택 코드가 누적 547,418,000달러와 분기 342,761,000달러를 선택했다. 기본 경로에서 잘못된 분기값 121,200,000달러를 재현한 공개 계산 검사는 복구 후 통과했고, 공시일인 2010-08-04까지 이전 분기를 유지한 뒤 8월 5일부터 새 값을 사용했다. 앞선 공시 파일 96개와 복구한 묶음 8개의 해시를 확인하고 캐시 재실행도 검증했다. 계약금 역시 차원 없는 XBRL 관측이므로 이 결과를 차원 검사만으로 모든 계정 범위를 판별했다는 증거로 해석하지 않는다.

같은 공시의 별도 재무상태표 행인 기타 유동부채 86,564,000달러를 미지급비용 307,965,000달러나 법인세 미지급금 9,013,000달러로 대체하는 규칙도 수정했다. `semantic_us_v4.arcana`는 해당 계정의 올바른 태그 `OtherLiabilitiesCurrent`를 포함하고 두 다른 계정의 대체 매핑을 제거한다. v3는 보존하며 104개 규칙 중 1개만 바뀌었다. 실제 공시·부적절한 대체값 방지 사례 4개를 포함한 관련 검사 58개와 하위 검사 7개가 통과했다. 네 종목의 정규화 대조에서 변경 계정은 기타 유동부채로 한정됐다. 기존 준비본은 원문 복구와 규칙 변경 이후 재준비 대상으로 표시하며, 운영 DB 게시와 전체 시장의 생존편향 해소 완료를 뜻하지 않는다.

최종 v4 준비본 6,704,660행과 9개 기준 지표의 507,492개 공시별 기간 계산을 대조해 차이가 없음을 확인했다. 공시 묶음 복구 전후에는 CELG 분기 5,626개·TTM 33,667개 팩터 값이 바뀌었고, 추가 기타 유동부채 규칙 수정 전후에는 준비된 전체 팩터 키·값이 같았다. 이는 해당 계정이 현재 293개 팩터 결과를 바꾸지 않았다는 비교이며 계정 검토가 불필요하다는 뜻은 아니다. [원천 복구·규칙 변경 검증](../data-lake/gold/survivorship/pipeline_verification/20260911_celg_rnd_scope/summary.json)과 [현재 재계산 준비 상태](../data-lake/gold/survivorship/us/financial_rebuild_preparation/20260911/summary.json)에 새 준비본을 연결했다. 전체 원천 계정 범위·공시 묶음의 완전성·운영 native 및 스냅샷 검증은 남아 있다.

정규 SEC 재무 공시 수집은 이제 `10-K`, `10-Q`를 요청할 때 각각의 `/A` 정정본도 포함한다. 정정본만 명시하는 호출도 지원하고, 안전한 폴더명 `10-K_A`, `10-Q_A`에 원래 공시번호와 양식을 보존한다. 정규화도 이 폴더를 읽는다. 확장된 양식 목록이 재개 작업의 식별 조건에 포함되므로 정정본 제외 상태로 완료된 예전 체크포인트를 그대로 재사용하지 않는다. 같은 공시를 다시 읽어도 수집 시각만 다르면 기존 메타데이터를 유지하며, 접수 시각 등의 실제 보완이 있으면 이전 JSON 원문을 Bronze의 `metadata_versions/{sha256}.json`에 먼저 보존한다.

복구 대상 4종목에서 보존된 재무 공시 이력 180건 중 묶음이 없던 167건을 확보했다. 각 종목의 해당 접수일 구간에 있는 추가 정정본까지 182건을 수집했으며, 180건 모두 공시번호·양식·접수일과 XBRL 파일 해시를 대조했다. 추가 ALXN `0000899866-17-000069`는 감사인 동의서 첨부, CELG `0000816284-19-000020`은 Part III 지배구조·보수 등의 보완으로, 본문에서 재무제표를 정정하지 않는다고 명시한다. 두 건에는 XBRL이 없어 현재 정규화기는 경고를 남긴다. 이 문서 범위의 자동 분류는 별도 미완료 항목이며, 단순히 정정본이라는 이유로 새 재무값을 만들지 않는다.

넓힌 수집 범위에서는 기존 CELG 메타데이터 12건에 비어 있던 접수 시각이 채워졌다. 최초 수집 실행의 무변경 검사는 이 차이 때문에 실패했으며, 기존 사본을 이전 해시와 대조하고 Bronze에 보존한 후 별도 재검증을 마쳤다. 본문·XBRL과 기존 공시일은 바뀌지 않았다. 4종목 모두 같은 수집 조건으로 재실행했을 때 캐시에서 재개되고 정규화 입력 해시가 유지됐다. 공개 HTTP 경계에서 정정본 수집·정규화·반복 수집·메타데이터 버전 보존을 검증한 9개 사례를 포함해 관련 64개 테스트와 하위 검사 7개가 통과했다.

새 공시 묶음의 Silver 정규화 결과는 기간별 8,309행, 공시번호별 8,405행이다. 직접 선택한 계정은 XBRL을 사용하며, 기존 준비본과 달라진 계정 셀 141개를 별도 보존했다. 매출 총액과 제품 매출, 리스 종류, 현금흐름 기초·기말 잔액 등의 의미 검토가 남아 있다. [공시 묶음 범위 검증](../data-lake/gold/survivorship/pipeline_verification/20260911_us_filing_bundles/summary.json)은 해당 접수일 구간의 수집·정규화 결과이며, 가격 전 구간의 재무자료 완전성이나 전체 시장·운영 재적재 완료를 뜻하지 않는다. 이전 670만 행 팩터 준비본은 새 코드·원천에 대한 재준비 대상으로 표시한다.

후속 계정 검토에서 같은 우선순위 목록의 태그를 XBRL 원문 순서로 선택하던 오류를 수정했다. 이제 선언된 태그 순서를 따르므로 ALXN·ATVI·CELG의 제품 매출이 전체 매출을 대신하지 않는다. 현금흐름표의 현금은 표시 구조의 `periodStartLabel`과 `periodEndLabel`이 함께 있는 합계를 선택한다. 부속 조정표의 현금 구성요소와 구분하고, 기초 잔액은 같은 공시의 현금흐름 기간 시작 직전일 관측을 사용한다. 기초 사실이 없으면 기말값으로 채우지 않는다. 공시 이력 소비자는 이 기초 관측일을 보고기간 종료일과 혼동하지 않으며, 실제 관측일·문맥·표시 역할은 공시별 Silver CSV에 보존한다.

규칙 v5는 104개 중 총포괄손익 규칙 하나만 수정해 비지배지분을 포함한 연결 합계를 먼저 선택한다. v4는 그대로 유지한다. 실제 공시와 결측 변형을 사용하는 새 공개 검사 8개를 포함해 회귀 검사 59개·하위 검사 7개가 통과했다. 최종 4종목 정규화는 기간별 8,309행·공시별 8,405행이며, 직전 전체 공시 정규화 대비 311개 값이 달라졌다. 이는 현금 잔액 226개, 매출·파생 매출총이익 48개, 감가상각 14개, 리스 6개, 판관비 15개, CELG 연결 총포괄손익 2개다. 이 전체 차이를 모두 의미 검토 완료로 분류하지 않는다.

최종 Silver 입력으로 4종목의 연간·분기·TTM 공개 계산 12개와 원문 기준값 7개를 확인했다. ATVI 2010년 4분기 매출은 직접 공시된 1,427백만 달러이며 연간·누적 반올림값을 차감한 1,428백만 달러로 대체하지 않는다. 첫 검증 프로그램의 이 기대값 오류와 수정 후 결과를 모두 보존했다. [계정 선택·공개 계산 검증](../data-lake/gold/survivorship/pipeline_verification/20260911_us_statement_accounts/summary.json)에 증거를 연결한다. 판관비와 리스의 부분 금액 대체, 상각비 범위, 매출원가 비교기간, 회사별 전체 재무 이력과 운영 native·스냅샷 재적재는 아직 검토 대상이다. 기존 670만 행 준비본은 계속 재준비 대상으로 유지한다.
