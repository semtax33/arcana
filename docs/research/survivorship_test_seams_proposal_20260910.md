# 상장폐지 적용의 테스트 범위 제안

상태: 구현 진행 중. 사용자의 후속 지시 “생존편향 처리 구현부터 먼저 진행해줘”에 따라 아래 세 공개 경계를 기준으로 테스트와 구현을 진행한다. 첫 검증은 실제 ClickHouse의 격리된 테스트 DB와 `BacktestService.run_factor_backtest`를 사용해 현금 합병 후 공급자 가격 대신 확정 대가가 자산가치에 반영되는지 관찰한다.

| 경계 | 사용자가 확인할 결과 | 첫 검증에 쓸 구체적 사례 |
| --- | --- | --- |
| 공식 자료 수집·파이프라인 실행 | 요청 기준일, 원문·해시, 재실행 결과, 누락·제공 불가 상태가 남는다. 계획·정정·보류를 실제 사건으로 오인하지 않는다. | Alpha `LISTING_STATUS`의 과거 목록과 DART 035480의 최초 일정→보류→수정 일정→사후 확정 공시 |
| 기준일별 투자 가능 종목군 | 현재 마스터에서 사라진 증권도 당시 상장 이력·공시·시총 근거가 있으면 계산 모집단에 들어간다. 상장 전·거래중단 후 신규 매수, 다른 발행사의 심볼 재사용을 구분한다. | 현재 마스터에는 없는 ATVI·TWTR·CELG·ALXN. 원본·당시 재무자료를 복구하고 해당 신호일 결과로 관찰 |
| 실제 FactorLab 백테스트 | 보유 종목의 현금·교환주식·조건부 권리·소각 결과를 자산가치와 매수 가능한 현금에 반영한다. 검증 불가능한 마지막 가격을 실현 대가로 간주하지 않는다. | ATVI 현금 95달러, CELG 현금+주식+CVR, ALXN ADS 단위, AVYA 기존 보통주 무대가 소각, 035480의 미확정 최종 실현가치 |

현재 공개 인터페이스는 Alpha 원본 수집의 `download_alpha_vantage_listings`, 리서치 종목군 생성 CLI의 `universe` 단계, 실제 서비스의 `BacktestService.run_factor_backtest`다. DART 수집은 기존 `OpenDartClient`와 `download_document`를 사용해 원본만 확보했다. 새 파이프라인 인터페이스는 확인된 첫 수집 사례를 구현하는 최소 범위에서 정한다.

테스트는 세 경계를 한꺼번에 구현하지 않고, 확인된 한 사례의 실패를 관찰한 후 필요한 부분만 고쳐 통과시키는 순서로 진행한다. 내부 파서 함수나 내부 협력 객체에 대한 목 검증 대신, 공개 실행 결과·반환된 종목군·실제 백테스트의 보유종목과 자산가치를 관찰한다. 데이터베이스가 필요한 검증은 격리된 연구 데이터베이스에서 수행한다.

공통 제약은 다음과 같다.

- 매 신호일의 시총 상위 70%는 종목 수 기준이며 팩터 결측·점수 정렬보다 먼저 결정한다. 시총이나 증권 식별이 없는 항목을 조용히 지워 모집단을 축소하지 않고 누락을 보고한다.
- 원본의 현재 상태, 조회 시각, 사건 효력 시각, 해당 정보를 알 수 있었던 공시 시각을 구분한다. 뒤늦은 확인 공시를 과거 신호에 사용하지 않는다.
- 미국 시세는 Alpha Vantage를 사용한다. 원문 거절·빈 응답은 가격 0이나 수익률 0의 근거가 아니다.
- 조건부 대가와 장외 잔존 주식을 확정 현금 또는 0으로 임의 변환하지 않는다. 불명확한 실행·평가 결과를 검증 완료 수익으로 표시하지 않는다.
- 스타일 점수 7개와 `lab_*`는 제외한다. 기존 고정 후보와 2024년 이후 평가를 보존하고, 자료 보정 후의 동일 기간 비교를 새로운 독립 검증으로 부르지 않는다.

관련 근거는 [자료 확보 기록](survivorship_baseline_20260910.md), [미국 합병 4건](../../deliverables/cross_market_top70_20260909/survivorship/US_four_merger_entitlements.json), [AVYA 소각](../../deliverables/cross_market_top70_20260909/survivorship/US_AVYA_cancellation_evidence.json), [DART 035480](../../deliverables/cross_market_top70_20260909/survivorship/KR_035480_delisting_evidence.json)에 있다.

추가로 첫 번째 범위에 사용할 원문 사례를 확보했다. 035480의 정정보고서 `20170202000370`은 접수번호 앞자리와 달리 실제 접수일이 2017-02-03이다. 최초 보고서와 정정본은 각각 보존돼 있으며 기존 정규화 함수의 두 CSV 결과는 같다. 이는 전체 공시가 같다는 뜻이 아니다.
