> 현재 실행 정책 (2026-09-12): 미국 상폐 모집단·날짜는 보관된 Alpha Vantage 목록에서 일괄 생성한다. SEC 공시 전수 수집은 중단했으며 아래 SEC 조사 기록은 과거 실험이다. 기본 파이프라인의 필수 단계나 재개 지시가 아니다. SEC는 필요한 분할·병합·합병 대가 근거를 조사하는 별도 용도로 사용한다.

# 생존편향·기업행위·재무 정규화의 공통 처리

2026-09-11 사용자의 일반화 요청에 따라 작업 단위를 종목에서 **반복 가능한 원인과 규칙**으로 전환한다. 전체 미국·한국 범위와 시총 상위 70% 종목 수 기준은 유지한다. 특정 종목의 숫자를 맞추는 보정 분기를 추가하지 않는다.

## 이미 있는 기반과 연결할 부분

- `engine/semantic/models.py`에는 기간·연결 범위, `COMPONENT_OF`, `SUBTOTAL_OF`, `DERIVED_FROM` 등의 관계가 있다.
- `engine/semantic/invariants.py`에는 동일한 의미의 재무값에 대한 회계식 검사와 `PASS`, `REVIEW`, `NOT_TESTABLE` 구분이 있다. 회계식이 맞는다는 이유만으로 매핑을 자동 변경하지 않는다.
- `engine/semantic/quality.py`, `unmapped.py`에는 범위별 커버리지와 미해결 원인 분류가 있다.
- SEC 정규화는 별도의 `SecFactCandidate` 선택 경로를 사용한다. 이 경로에서 원문 본표의 역할, 총액·구성요소 관계를 공통 의미 모델과 연결하는 것이 우선이다. 새로운 종목별 정규화 엔진을 만들지 않는다.
- 생존편향 파이프라인의 현재 검토된 종목 목록은 증권 식별을 위한 임시 검증 범위다. 전체 시장 지원의 완료 기준으로 사용하지 않는다. 자동 증거 검증을 통과한 사건·상장 이력을 공급자 어댑터가 같은 증권 이력 모델로 제공하도록 확장한다.

미해결 재무값을 격리해도 증권을 당시 투자 가능 모집단에서 지우지 않는다. 시총 상위 `ceil(N * 0.7)`는 팩터 결측과 점수 정렬보다 먼저 결정하며, 이후 결측·자료 부족으로 계산하지 못한 기회를 커버리지에 표시한다. 수집 성공, 값의 의미 검증, 팩터 커버리지는 별도로 보고한다.

## 실행 순서와 검증 비용

1. 현재 후보를 공통 검토 사유로 분류하고 시장·공시 형태·기간별 개수를 집계한다. 같은 원인을 개별 기업마다 다시 조사하지 않는다.
2. 본표의 총액·구성요소 관계를 공통 선택기에 연결한다. D&A, 판관비, 리스는 같은 규칙을 검증하는 서로 다른 예제로 사용한다.
3. 각 규칙의 대표 정상 사례와 반례를 공개 정규화 경계에서 검증한다. 다른 발행사와 문서 구조의 표본으로 기업에 종속되지 않는지 확인한다. 표본 통과를 전체 시장 검증으로 부르지 않는다.
4. 변경된 규칙·원문에 영향을 받는 공시만 다시 계산한다. 규칙을 하나 바꿀 때마다 전체 가격 이력과 모든 팩터를 재적재하는 반복을 피한다.
5. 공통 규칙 묶음이 안정되면 시장 전체에 일괄 적용해 품질·커버리지 결과를 확인하고, 승인된 계산 범위의 팩터·스냅샷을 재적재한다. 미해결 예외는 원인별 목록에 유지한다.

원문은 Bronze, 정규화·증거·검토 목록은 Silver, 사용자용 데이터와 커버리지 요약은 Gold에 저장한다. 기존 원문 캐시의 Bronze 밖 경로도 이 구조에 맞게 정리해야 한다. 스타일 점수 7개와 `lab_*`는 전략 작업에서 제외한다.

## 현재 관측과 다음 작업

보관된 미국 4종목의 180개 재무 공시·8,384개 정규화 행에서, D&A 범위가 겹칠 가능성이 있는 108개 후보를 우선 태그 관계 기준 3개 검토 그룹으로 묶었다. 이는 **108개 오류를 확인했다는 뜻이 아니다**. 본표 관계를 확인해야 같은 그룹 안에서도 합계·개별 금액·반올림 차이를 구분할 수 있다.

검토 자료는 `data-lake/silver/survivorship/generalization/20260911`에, 사용자용 범위는 `data-lake/gold/survivorship/generalization/20260911/summary.json`에 있다. 이후 같은 선택·검증 체계를 DART 경로와 상장·기업행위 원장 처리에 적용한다.

## 공시 식별 정보의 공통 추출

SEC 재무 정규화가 이미 읽은 XBRL 사실과 문맥에서 CIK, 공시된 발행사명, 종목코드, 주식 종류, 거래소를 함께 추출한다. 같은 발행사 문맥만 사용하고 여러 주식 종류는 문맥별로 보존한다. 요청에 사용한 종목코드와 공시에 적힌 코드는 별개로 저장한다. 과거 공시에 항목이 부족하면 회사별 예외를 추가하지 않고 공통 검토 사유로 남긴다.

이 관측만으로 상장 기간이나 합병 대가를 확정하지 않는다. 공시 발표일과 공시 대상 기간도 따로 보존한다. Alpha 목록 후보와의 연결 단계는 실제 공시된 코드·이름·거래소·주식 종류와 날짜의 모순을 검사한다. 회사명은 대소문자·공백·구두점만 정리하며 유사도나 회사별 별칭으로 맞추지 않는다. 같은 코드의 다른 CIK가 관측되면 이름이 맞는 공시만 골라 충돌을 숨기지 않는다. 연결된 후보도 확정 증권 이력으로 자동 승인하지 않는다.

`survivorship` 실행에 이 연결을 포함했다. 원본과 파생 관측의 해시를 다시 확인하고, 기준일·목록 버전·SEC 관측·코드가 같은 연결 결과는 재사용한다. 보관된 미국 목록 24,283개 공급자 키 모두를 유지한 실제 실행에서, 현재 180개 SEC 식별 보고서로 충돌 없이 연결된 후보는 3개였다. 전체 82개 목록·653,829개 원본 관측과 연결을 포함한 실행은 36.28초, 재실행은 2.45초였다. 아직 공식 식별 관측이 없는 후보가 대부분이며, 숫자를 높이려고 과거 종목을 제외하거나 연결 기준을 낮추지 않는다.

## 첫 공통 규칙의 구현

US v7 규칙은 종목명 대신 공시의 본표 위치, 해당 표의 표준 기준 계정, 표시된 금액의 의미를 함께 검사한다. 현금흐름표의 D&A 합계는 별도 `DNA_CF` 계정으로 보존한다. Python 팩터 계산, JavaScript 커버리지 계산, 정규화 검증 보고서와 의존 관계의 계산 가능 판정도 이를 사용한다.

- 같은 본표에 영업현금흐름 기준 계정이 있고 D&A 합계만을 뜻하는 표시명이 있어야 한다. 다른 비용까지 포함한 금액은 합계로 채택하지 않는다.
- 본표 근거가 없는 Company Facts의 합산 태그를 순수 감가상각비로 바꾸지 않는다. 금융비용 상각도 무형자산 상각과 구분한다.
- 보고된 합계가 있으면 주석의 구성항목을 더하지 않는다. 합계가 없으면 감가상각비와 무형자산상각비가 모두 있어야 구성항목 합산을 시도한다. 명시적인 0은 유지하며 결측을 0으로 바꾸지 않는다. 기간·범위가 같은지에 관한 기존 제약은 별도로 적용된다.
- 본표 위치의 증거를 기존 `SemanticContext` 구조로 저장한다. 이를 연결·별도 재무제표의 비교 가능성까지 확인했다는 뜻으로 확대하지 않는다.

실제 공시 3개에서 17,616,000달러, 544,848,000달러, 198,000,000달러의 보고 합계가 공개 팩터 계산까지 전달됨을 검증했다. 본표 누락, 다른 비용이 섞인 금액, 불완전한 구성항목, 명시적인 0 등의 반례를 포함한 공개 경계 검증 44개가 통과했다. 이 숫자는 전체 시장 검증 수가 아니다. 보관된 미국 공시의 일괄 적용 결과와 재계산 대상은 `data-lake/silver/survivorship/financial_research/us_primary_statement_scope_20260911`에 보존한다.

상장 이력과 기업행위 원장의 전 시장 자동 수용, 전체 팩터 재적재, 생존편향을 반영한 전략 검증은 여전히 남아 있다. 재무값의 미확정을 이유로 과거 증권을 모집단에서 제거하지 않는다.


## 상장 관측의 일괄 처리와 재사용

미국 상장 관측도 정규 `survivorship` 갱신에서 처리한다. 새 다운로드 여부와 무관하게 보관된 Alpha Vantage 목록을 읽고, 원문·조회 조건·해시·수집 시각을 검증한 뒤 Silver에 날짜별 관측을 보존한다. [공식 LISTING_STATUS 문서](https://www.alphavantage.co/documentation/#listing-status)는 과거 기준일의 미국 주식·ETF 상태 목록을 제공한다고 설명한다. 이 응답을 법적 발행사 식별이나 합병 대가로 확장 해석하지 않는다.

공급자 키는 심볼·거래소·자산 종류·IPO일의 조합이다. 이를 증권 ID로 대체하지 않고, 조회 기준일과 실제 수집 시각을 각각 남긴다. 심볼의 복수 키, 이름·폐지일 변경, 같은 기준일의 상태 충돌, 누락·잘못된 날짜를 공통 사유로 분류한다. 원인별 개수는 서로 겹칠 수 있으며, 충돌이 탐지되지 않은 후보도 발행사·주식 종류 확인이 끝난 것은 아니다.

각 원문과 메타데이터의 해시·정규화 코드 버전으로 처리 결과를 구분한다. 변경되지 않은 파일은 재사용하고 한 파일 변경 시 해당 파일만 다시 정규화한다. 같은 원문 세트와 기준일의 분류 결과도 재사용하며, 다른 기준일의 결과는 별도 세대로 저장한다. 이전 처리 세대와 원문은 유지한다.

보관된 82개 목록(2016-12-30~2026-09-10, active 40개·delisted 42개)의 653,829개 관측·24,283개 공급자 키를 처리했다. 해당 환경에서 첫 실행은 34.14초, 동일 입력 재실행은 1.77초였고 82개 파일과 후보 분류 결과를 모두 재사용했다. 공개 갱신 경로 38개 검증이 통과했으며 원본 필드 전체와 날짜·수집 시각을 실제 자료에서 대조했다. 연속된 일별 전 시장 커버리지, 확정 증권 연결, 최종 대가 및 DB 재적재 완료를 뜻하지 않는다.

검증 근거는 Silver `survivorship/financial_research/us_listing_history_generalization_20260911`, 사용자용 결과는 Gold `survivorship/pipeline_verification/20260911_us_listing_history_verified`에 있다. 다음 단계는 이 공통 후보 인덱스에 공식 발행사·증권 근거를 연결하고, 같은 처리 구조를 DART 상장 이력에 적용하는 것이다.


## 공식 식별 원본 범위 확대 준비

SEC 현재 코드–CIK 목록 10,407행·8,013개 발행사 ID를 한 요청으로 확보하고 원본·변환본·출처를 분리 보존했다. 복수 주식 종류를 CIK 기준으로 너무 일찍 중복 제거하던 수집 문제도 수정했다. Company Facts 다운로드는 모든 코드를 해석하되 CIK당 한 번만 수행한다. 현재 목록은 과거 상장 이력이 아니다.

다음 역사 자료 수집은 회사마다 같은 API를 반복하기 전에 SEC 전체 제출 이력 배포본을 검토한다. [SEC API 문서](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)는 전체 제출 이력의 야간 ZIP과 현재·이전 회사명, 거래소·코드 정보를 설명한다. 이번 단계에서 그 전체 ZIP을 수집하거나 과거 증권 이력을 승인한 것은 아니다.


SEC 전체 제출 이력 배포본을 실제 수집하고 메타데이터 인덱스까지 연결했다. 약 98만 신고주체의 원문을 한 요청으로 보존했으며, 원본과 코드가 같으면 인덱스도 재사용한다. 이로써 기존 네 발행사 공시 표본을 넘어 현재·이전 이름과 과거 공시 위치를 일괄 조사할 기반을 확보했다. 다음 단계는 Alpha의 모든 역사 후보를 이 이름·CIK 근거와 대조해 추가 공시 수집 대상을 묶는 것이다. 이름 일치만으로 증권 이력이나 합병 대가를 승인하지 않는다.


전체 SEC 이름 인덱스와 Alpha 후보의 일괄 대조까지 파이프라인에 연결했다. 약 98만 신고주체를 한 번 스캔해 24,283개 공급자 후보를 보존하고 7,621개 CIK의 공시 수집 목록을 만들었다. 이름이 유일하더라도 증권 이력을 승인하지 않으며 복수 CIK를 임의로 줄이지 않는다. 다음은 이 목록의 기본·추가 제출 이력 JSON을 ZIP 한 번 열기로 일괄 조회해, 필요한 과거 공시의 종류·접수번호·날짜를 수집 계획에 연결하는 단계다. 종목마다 ZIP을 다시 열거나 같은 CIK의 공시를 반복 다운로드하지 않는다.

이 공시 목록 처리도 구현했다. 7,621개 CIK의 기본 이력과 참조된 추가 이력을 하나의 ZIP 세션에서 읽어 6,871,881개 공시 관측을 보존했다. 공통 서식 분류로 거래소 등록 제거 통지 7,646행, 보고 의무 종료 통지 4,262행, 재무보고서 367,830행, 거래 관련 문서 96,727행 등을 분리한다. 이는 원문 공시 목록의 행 수이며 사건 수나 확정 상장폐지 종목 수가 아니다. 본문 다운로드와 효력일·대가 추출은 후속 단계다.

일반화의 단위는 종목이 아니라 **자료 형식과 사건 유형**이다. 공급자별 수집기는 Bronze에 원본을 남기고, 공통 정규화기가 Silver의 증권 이력·사건 근거를 만든다. 검증된 사건만 수정가격과 과거 투자 가능 종목 집합에 적용하고 Gold로 제공한다. 동일 입력은 재사용하며, 새로운 예외는 종목명 조건을 추가하기보다 같은 원인에 적용되는 규칙과 회귀 검증으로 해결한다. 이 전체 설계 중 자동 사건 승인과 DART 대응, 가격·재무·팩터의 전체 재적재는 아직 완료되지 않았다.

통지 원문 수집과 Form 25 XML의 증권 종류 추출도 공통 경로에 연결했다. 예를 들어 AAR의 2020-10-06 Form 25는 `Preferred Stock Purchase Rights`에 관한 통지다. 이를 회사 보통주의 상장폐지로 처리하면 생존편향을 보정하는 과정에서 잘못된 제외가 발생한다. 정규화는 회사명만 사용하지 않고 공시의 발행사·거래소·증권 종류를 각각 보존한다. 규칙에는 종목별 분기가 없으며, XML이 없는 옛 텍스트·HTML 통지와 날짜·식별 충돌은 공통 검토 사유로 남긴다.
